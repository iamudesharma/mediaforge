# Taste
- Keeps shared packages app-agnostic: never add consumer-specific classes, app settings or unrelated domain logic (e.g. torrent/PeerStream code) to a reusable package. Everything a consuming app needs must be reachable through the package's published public API. Confidence: 0.85
- Treats an explicit scope as hard: when told to work only inside certain packages and not to modify another, code outside that boundary is untouchable. Confidence: 0.75
- Performance-critical media/GPU work belongs in the native layer (Rust/GPU between decode and presentation), not in Dart. Avoids CPU filters, CPU pixel copies, RGBA round-trips and unnecessary texture recreation; frames should stay on the GPU end to end. Confidence: 0.8
- New features must be additive and backward compatible, opt-in and off by default, and changeable at runtime without reopening media or restarting the engine. Prefers enums/config objects over magic numbers, and stable wire/string names for anything that appears in logs or diagnostics. Confidence: 0.75
- Exposes capability/support queries publicly, and requires unsupported devices to silently keep the existing path rather than fail — a new optional feature must never break the core feature. Confidence: 0.7
- Core playback stability outranks any added quality feature: the new stage must never cause rebuffering, A/V desync, clock changes, network/torrent behavior changes or seek resets, and must gracefully degrade or bypass instead of oscillating or failing. Confidence: 0.85
- Expects the feature's existing behavior, color/format correctness, aspect/rotation, subtitles, fullscreen and audio to be explicitly preserved, with a fallback reason recorded whenever the new path is skipped. Confidence: 0.75
- Does not accept unmeasured performance or quality claims. Numbers must be benchmarked on real hardware for the stated matrix and clearly labeled as measured; not-yet-measured work is called out as such. Confidence: 0.9
- Expects a feature to ship with tests covering defaults, runtime changes, state propagation, capability fallback, unsupported paths, non-regression of core behavior (seek/audio/subtitles/fullscreen), resource cleanup, "no extra work while paused/backgrounded", and — for a bug fix — a regression test pinned to the exact reported scenario, asserting exact values (e.g. the exact string the engine must receive) with existing tests kept green. Confidence: 0.75
- Prefers one shared predicate for logic that spans layers: the controller and every caption overlay/widget must gate on the same helper instead of each re-implementing a similar-looking condition. Confidence: 0.65
- Normalizes representations at the language boundary: `file:` URIs are converted to plain filesystem paths before reaching the native engine (never `file:///...`), while remote http(s) URLs pass through verbatim. Confidence: 0.6
- Requires a fix to be verified end-to-end against the real engine with a real file, not only against fakes/mocks. Confidence: 0.7
- Wants failures surfaced to the caller/user (try/catch plus an explicit error message/snackbar) instead of failing silently. Confidence: 0.6
- Wants state transitions to be deterministic: selecting Off must close or hide the external session unambiguously, and stale track/session state must never leak across source changes. Confidence: 0.6
